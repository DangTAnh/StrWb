<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> auth routes | Login POST carries credentials + CSRF token across this boundary |
| client -> admin routes | Session cookie authenticates; unauthenticated requests must never reach handlers |
| app -> SQLite | Credential lookup against admin_users; hashes stored, never plaintext |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Elevation of Privilege | Open redirect via `next` param on login | mitigate | `next` must start with `/` and not `//`; else fall back to `url_for('admin.dashboard')`; unauthorized_handler passes only `request.path` (D-15) |
| T-02-02 | Spoofing | Brute-force login | accept | D-12: single admin, low exposure risk; rate-limiting deferred to Phase 4 (internet-exposed hardening) |
| T-02-03 | Spoofing | Session fixation / forgery | mitigate | Flask-Login `login_user` regenerates session; strong SECRET_KEY from Plan 01; `SESSION_COOKIE_HTTPONLY=True`, `SAMEsITE=Lax` |
| T-02-04 | Tampering | CSRF on login/logout POST | mitigate | Flask-WTF `CSRFProtect` initialized globally; `form.hidden_tag()` renders token; logout is POST-only |
| T-02-05 | Information Disclosure | Unauthenticated admin page access | mitigate | `@admin_bp.before_request` + `@login_required` on all admin routes; `login_view='auth.login'` |
| T-02-06 | Information Disclosure | Plaintext credential storage | mitigate | Werkzeug `check_password_hash` against scrypt hash from Plan 01 init-db; no plaintext compare |
</threat_model>
