<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> rendered templates | User-controlled values (flash messages, username) rendered into HTML; Jinja autoescape is the only defense |
| client -> error handlers | Unhandled exceptions surface here; must never leak internals |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | XSS via user-controlled template data (username, flash text) | mitigate | Rely on Jinja2 autoescape (default ON); never use `|safe` on user-derived values; username rendered as plain text |
| T-03-02 | Information Disclosure | Stack trace / internals leaked on 500 | mitigate | Generic 500 handler returns `errors/500.html`; `db.session.rollback()`; no traceback template; DEBUG defaults off (Plan 01) |
| T-03-03 | Tampering | CSRF on logout POST form in nav | mitigate | Logout form includes `<input type="hidden" name="csrf_token" value="{{ csrf_token() }}">`; CSRFProtect global from Plan 02 |
| T-03-04 | Denial of Service | Oversized page payload / heavy CSS | accept | Stylesheet target <5KB; no external runtime JS; low-value static site |
</threat_model>
