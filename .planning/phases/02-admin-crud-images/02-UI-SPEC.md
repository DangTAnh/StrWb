# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Flask server-rendered Jinja2 templates with hand-written CSS |
| Preset | not applicable |
| Component library | none (hand-rolled components: button, table, badge, gallery, flash) |
| Icon library | none (unicode arrows `↑` `↓` for gallery reorder only; all other actions are text links/buttons) |
| Font | Noto Sans VN (Google Fonts) — Vietnamese diacritic support confirmed; fallback system-ui/sans-serif |

**Design system source:** Phase 1 baseline (01-UI-SPEC.md) — Phase 2 **extends** the existing system, does not introduce a new one. Tool stack unchanged: Flask + Jinja2 + plain CSS (CLAUDE.md "What NOT to Use" bans Tailwind, Bootstrap, React/Vue, shadcn). The shadcn initialization gate does NOT apply — Python Flask project, not React/Next/Vite.

**Extensions Phase 2 adds to the Phase 1 system (documented in this contract):**
1. **Border-radius tokens** — Phase 1 declared none; Phase 2 introduces components (badges, thumbnails, buttons, dialogs) that need radius: `sm` 4px, `md` 8px.
2. **Semantic status palette** — 3 badge colors reserved for product status only (`Còn hàng` / `Hết hàng` / `Ngừng bán`). Base 60/30/10 palette (#F9FAFB / #FFFFFF / #2563EB) is unchanged.
3. **Button component** — primary / secondary / destructive (Phase 1 had no buttons beyond the login submit).
4. **Warning flash color** — Phase 1 defined success (#059669) and error (#DC2626); Phase 2 adds warning (#D97706) for D-09 (image-cleanup warning) and D-17 (blocked batch).
5. **Minimal vanilla JS** — Phase 1 was zero-JS; the admin product form gains one inline script (~1–2KB, no library) for gallery preview + reorder. Public pages remain zero-JS. This is required by PITFALLS.md UX ("No image preview on upload form").

## Spacing Scale

Declared values (all multiples of 4 — inherited from Phase 1):

| Token | Value | Phase 2 Usage |
|-------|-------|---------------|
| xs | 4px | Label-to-input gap, badge horizontal padding, required-asterisk spacing |
| sm | 8px | Table cell vertical padding, action-link gap, form field margin-bottom |
| md | 16px | Table cell horizontal padding, form container padding, flash spacing |
| lg | 24px | Card padding, gallery grid gap, action-row gap |
| xl | 32px | Empty-state padding, page max-width horizontal padding |
| 2xl | 48px | Table thumbnail box (48×48px), major section breaks |
| 3xl | 64px | Not used in Phase 2 — reserved for catalog grid (Phase 3) |

**Exceptions:**
- Touch targets stay **minimum 44×44px** (Apple HIG / WCAG 2.1 AAA) for every button and the table action links `Sửa` / `Xóa` and the gallery reorder buttons `↑` `↓`. In dense table rows this is achieved via cell padding around the links, not by enlarging text.
- Gallery thumbnail display boxes: 96×96px (gallery preview) and 48×48px (table thumbnail) — these are non-interactive image boxes, exempt from the 44px rule.

### Gallery Section

**Existing-image gallery (edit mode — D-14):** flex/grid row, `lg` 24px gap, wrap.

```
[Gallery item — width 96px]
  ├── [Image] 96×96px, radius md, border 1px #E5E7EB, object-fit cover
  │          click → full-size image in new tab (generated thumb asset)
  ├── [Badge "Ảnh chính" — top-left overlay, only on first item] (D-12)
  ├── [Reorder buttons — under image]
  │     [↑] [↓] 44×44px touch, text #6B7280, hover #2563EB (D-13)
  └── [Delete control — under image]
        [☐] Xóa  (checkbox, Label 14px) (D-15)
```

- Gallery order = persisted order. First item carries the "Ảnh chính" badge; moving an item to position 1 makes it primary (D-12).
- Delete is **not immediate** — checkbox only; deletion happens on "Lưu sản phẩm" submit (POST + CSRF, D-15).
- Reorder uses **up/down buttons** (`↑` `↓`), not drag-and-drop — simpler, keyboard-accessible, zero libraries (Claude's Discretion, D-13).

**New-file upload (create & edit mode — D-11, D-10):**
- File input `type="file" multiple accept=".jpg,.jpeg,.png,.webp"` labeled "Chọn ảnh".
- On selection: client-side preview thumbnails render (vanilla JS, `URL.createObjectURL`) in the same 96×96 gallery grid style, appended after existing items.
- New previews get the same reorder `↑` `↓` buttons; gallery order (existing + new) is the order saved on submit.
- **No client-side validation** — server is the source of truth (D-16/D-17). A client-side `accept` attribute only filters the picker; a non-conforming file is caught server-side and reported per D-17.
- **Known limitation (documented):** on server-side validation failure the form re-renders, so newly selected files are lost (browsers cannot resend file inputs). Flash + field errors explain the reason; the admin re-selects. Do not over-engineer client-side file persistence — D-17 requires rejecting the batch, not silently keeping part of it.

## Interaction Contracts

### Product list flow
1. GET list, sorted `sort_order` ASC, tie-break `id` ASC (D-02), paginated 20/page (D-03).
2. "Thêm sản phẩm" → create form. "Sửa" → edit form. "Xóa" → confirmation page.
3. Empty list → empty state block with "Thêm sản phẩm" CTA.

### Create/Edit form flow
1. GET renders form (empty for create, pre-filled for edit).
2. On POST: validate all fields **and all gallery files as one batch**.
   - Any invalid file (wrong extension / magic bytes / Pillow verify fail / >2000×2000px / batch over 16MB — D-16) → **reject the entire batch** (D-17), flash the offending filename + reason, render form with errors. No partial save of the image batch.
   - Save order: first gallery item = primary (D-12); thumbnails generated (IMG-04); files stored with UUID names (IMG-02); original Vietnamese filename kept in DB (D-16, PITFALLS — no `secure_filename` for display names).
3. On success → redirect to product list with success flash.
4. Gallery reorder and per-image delete are **persisted only on submit** (D-15).

### Delete flow
1. GET `/delete` renders confirmation showing product name (D-04) + image count (D-05) + irreversible warning (D-08).
2. POST `/delete` (CSRF token) → delete DB row **first**, then clean up image files from disk (D-06, prevents half-done errors).
   - Disk cleanup failure (missing/locked file) → log warning flash, **does not block** the deletion (D-09).
3. Redirect to list with flash "Đã xóa sản phẩm “{tên}”{ và N ảnh đã xóa}" (D-07).

### Status derivation (D-08, PROD-04/PROD-05)
- `quantity > 0` and not discontinued → **Còn hàng**
- `quantity = 0` and not discontinued → **Hết hàng**
- `discontinued` = true → **Ngừng bán** (overrides quantity)
- Displayed as a badge in the table; hinted live in the form (derived-status text under Tồn kho).

### Image reorder mechanism (D-13)
- Up/down buttons on each gallery item; first position = primary image (D-12).
- Existing DB images: reorder translates into the order value submitted on save (hidden field carrying ordered image ids).
- New previews: vanilla JS reorders the local array and re-renders previews; the final order is submitted with the files.
- First item in the displayed gallery order is always the one marked "Ảnh chính".

### Flash messages
- Single flash zone per page, above content (inherited Phase 1 pattern).
- Success #059669, error #DC2626, warning #D97706 (new).

### Accessibility (inherited + Phase 2)
- `lang="vi"`, `charset="utf-8"`, skip link from Phase 1 base template.
- Every form input has an associated `<label>`; required fields marked with `*` and `aria-required`.
- Table uses semantic `<table>` + `<th scope="col">` + visually-hidden `<caption>`.
- Gallery checkbox "Xóa" has a visible label and an `aria-label` including the image index/filename.
- Reorder buttons carry `aria-label` "Chuyển lên" / "Chuyển xuống"; disabled state at first/last position.
- Delete confirmation is a real page (no JS `confirm()`) — keyboard/screen-reader accessible.
- Touch targets 44px minimum on all interactive elements.
- Status badges: colored text on tinted background meets WCAG AA contrast (verified for #059669/#ECFDF5, #D97706/#FFFBEB, #6B7280/#F3F4F6).
- Focus visible: 2px #2563EB ring on all interactive elements.
