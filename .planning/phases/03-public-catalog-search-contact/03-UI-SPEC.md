# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Flask server-rendered Jinja2 templates with hand-written CSS |
| Preset | not applicable |
| Component library | none (hand-rolled components: site header + search form, product card, badge overlay, gallery-detail, contact strip, messenger button) |
| Icon library | none (text labels only: "Tìm", "Mua qua Messenger", "Trước" / "Sau") |
| Font | Noto Sans VN (Google Fonts) — inherited Phase 1; fallback system-ui/sans-serif |

**Design system source:** Phase 1 baseline (01-UI-SPEC.md) + Phase 2 extensions (02-UI-SPEC.md). Phase 3 **extends** the existing system, introduces no new design system. Tool stack unchanged: Flask + Jinja2 + plain CSS (CLAUDE.md "What NOT to Use" bans Tailwind, Bootstrap, React/Vue, shadcn). The shadcn initialization gate does NOT apply — Python Flask project, not React/Next/Vite.

**Extensions Phase 3 adds to the Phase 1+2 system (documented in this contract):**
1. **Public site header + search form** — `base.html` gains a `{% block header %}`; a public nav (brand link + GET search form) is provided by all public templates via a shared include. Admin pages render no header (search is a public-only feature, D-09).
2. **Product card component** (grid) — thumb (aspect 1:1, `object-fit: cover`), name, price, status badge overlay; dimmed image for out-of-stock/discontinued (D-04).
3. **Status badge overlay on image** — reuses the Phase 2 badge palette, new `.badge-overlay` positioning class.
4. **Gallery-detail component** — main image + clickable thumbnail strip (D-06), main image swap via one tiny inline vanilla JS snippet (~10 lines, no library). Phase 1/2 public pages were zero-JS; this is the single justified exception.
5. **Messenger CTA** — "Mua qua Messenger" primary button on detail + contact strip on homepage (D-13); reuses `.btn-primary`.
6. **Contact strip** — homepage section satisfying CONT-01/CONT-02.

## Spacing Scale

Declared values (all multiples of 4 — inherited from Phase 1, all verified):

| Token | Value | Phase 3 Usage |

- Search input horizontal padding 12px and gallery-thumb padding 0 are the only non-token paddings; both are inputs/border-box, declared inline (matches Phase 2 precedent of declaring 12px input padding as an exception).

### Base Template (`base.html`) — one structural change

Insert a `{% block header %}{% endblock %}` between the skip-link and the flash-zone. Admin templates do not override it → admin pages render no header. Public templates extend a new `public/base.html`:

```
{% extends "base.html" %}
{% block header %}{% include "public/_nav.html" %}{% endblock %}
```

`public/index.html`, `public/product_detail.html`, `public/search.html` all extend `public/base.html`. Error templates (404/500) keep extending `base.html` (no header — minimal error pages).

## Interaction Contracts

### Route map (all public, no login — CAT-01)

| Route | Method | Purpose |
|-------|--------|---------|
| `/` | GET | Homepage catalog grid, page 1 (CAT-01, D-01..D-04) |
| `/?page=N` | GET | Paginated grid (12/page, D-03) |
| `/products/<int:product_id>` | GET | Product detail (CAT-02, CAT-03, CAT-05, D-05..D-08, D-13) |
| `/search?q={từ khóa}` | GET | Search results (SRCH-01, D-10..D-12) |

- Sort order on both grid + search: `sort_order` ASC, tie-break `id` ASC (inherited Phase 2 D-02).
- `404` if `/products/<id>` not found → render the existing 404 template (link back to home).

### Search flow (D-10, D-11)

1. GET `/search` receives `q`. Strip whitespace.
2. If `q` empty → render empty-query prompt state (no query is not an error, just a prompt).
3. Diacritic-insensitive match (D-11): normalize both the query and each product's `name` + `description` using `unicodedata.normalize('NFD', ...)` → strip combining marks → `casefold()`, then substring match. "ao" matches "áo". Mechanism delegated to planner (recommended: normalize in Python and filter the catalog in memory — single admin, low volume; exact approach: in-Python filter vs stored normalized column is a plan decision).
4. Match is on `name` OR `description` (SRCH-01).
5. Results rendered through the shared product-card include (D-12), 12/page, pagination links carry `q`.
6. Zero matches → no-results state (exact copy above).

### Gallery thumbnail swap (D-06)

Inline vanilla JS in `product_detail.html` (single `<script>`, ~10 lines, no library):

```
- find #main-image; if missing, exit
- querySelectorAll('.gallery-thumb') → click listener per thumb
  - preventDefault
  - main.src = thumb.dataset.src; main.alt = thumb.dataset.alt
  - remove .is-active + aria-current from all thumbs; add to clicked thumb
```

Each `.gallery-thumb` is a `<button type="button">` carrying `data-src`/`data-alt`. First thumb is `.is-active` by default in markup (D-12: first image = main).

### Messenger interactions (D-13, CONT-01, CONT-02)

- All Messenger CTAs open `config['MESSENGER_URL']` in a new tab: `target="_blank" rel="noopener"`.

## Decisions Flagged

Ambiguities resolved with a reasonable choice rather than a user question:

1. **Search lives only in the public header, not admin.** D-09 says "header trang chủ". `base.html` is shared, so Phase 3 adds a `{% block header %}` that only public templates fill. Admin pages keep their existing dashboard-side nav and gain no search box.
2. **Price uses the accent token.** Detail price is Display 32px/600 #2563EB; card price is Body 16px/600 #2563EB. "Giá nổi bật" (D-08) achieved via accent color — a documented extension of the accent reservation list.
3. **Detail goes 2-column at 768, not 1200.** D-05 says "desktop ảnh trái — thông tin phải". With a 360px gallery column the 2-col layout fits at 768; it widens to 440px at 1200. Uses only the declared 480/768/1200 breakpoints.
4. **Detail main image reuses the 400px thumbnail (IMG-04).** No new full-size render variant is generated. At 2x DPR a 440px box ideally wants ~880px, but MVP performance (PITFALLS: >2s mobile loads) favors the existing 400px asset. Upgrade path: add a mid-size render in a later phase if image sharpness is an issue.
5. **Out-of-stock red line copy.** D-07 specifies a red "Hết hàng" line. The badge already says "Hết hàng"; the red line uses the fuller copy "Sản phẩm hiện đang hết hàng." in #DC2626 to add information (not duplicate the badge). This reuses the destructive token for a status alert — deliberate, not a destructive action.
6. **Messenger button shown for discontinued products too.** D-07 only mandates the button for out-of-stock; CONT-02 mandates a visible Messenger button on detail. Simplest consistent choice: button on all statuses, red alert line only for out-of-stock.
7. **Search normalization mechanism delegated to planner.** UI contract fixes the behavior (diacritic-insensitive, matches name OR description). Whether to filter in Python or add a stored normalized column is a plan decision; recommended in-Python NFD+strip+casefold over the small catalog.
8. **Search page omits the contact strip.** The Messenger CTA appears on home (strip) + detail (button); the search results page is a navigational page and skips it to avoid redundancy.
9. **Back link uses same-origin referrer.** Preserves search→detail context (PITFALLS back-link pitfall); falls back to home for direct visits.
10. **One tiny JS snippet on public pages.** Phase 1/2 public was zero-JS; the gallery thumbnail swap (D-06) is the single exception — ~10 lines vanilla, no library, graceful when JS off.
