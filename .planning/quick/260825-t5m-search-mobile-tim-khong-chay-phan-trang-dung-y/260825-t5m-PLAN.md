# Quick Task 260825-t5m: Sửa tìm kiếm mobile — Tìm không chạy + phân trang đứng yên trang 1

## Root cause (đã kiểm chứng bằng test_client)

1. **search-ajax.js dùng fetch POST** nhưng app bật `CSRFProtect` global → mọi
   POST `/search` không kèm csrf_token bị chặn **400**. `.then(r => r.json())`
   parse HTML lỗi → throw → `.catch` → `form.submit()` reload `/search?q=…`
   **mất page** → luôn về trang 1. Đây là lý do "bấm trang 2/3/4 vẫn đứng
   trang 1" và nút Tìm trông như không làm gì.
2. **`_pagination.html` chỉ chứa `{% macro %}`** — route AJAX
   (`admin.py`-style: `render_template('public/_pagination.html', ...)`) nhận
   chuỗi RỖNG → nếu AJAX thành công thì pagination biến mất.
3. **public.py:96-97**: `request.args.get('page', request.form.get('page', 1),
   type=int)` — Werkzeug trả default NGUYÊN TRẠNG khi key không ở args →
   `'2'` (string) → `_manual_pagination` gọi `min('2', int)` → TypeError 500
   (luồng POST hiện bị CSRF chặn trước, nhưng sửa luôn cho đúng).

Đã verify: POST ajax → 400; GET `/?q=&page=2` → 200; render trực tiếp
`_pagination.html` → len 0.

## Task 1: search-ajax.js — POST → GET

**Files:** `app/static/js/search-ajax.js`

Trong `runSearch(q, page, push)`:

- Thay block FormData + fetch POST bằng GET querystring (search là read-only,
  GET không bị CSRFProtect chặn, và route đọc args `type=int` chuẩn):

```js
    const params = new URLSearchParams({ q: q, page: String(page), ajax: '1' });
    const url = (form.getAttribute('action') || window.location.pathname) + '?' + params.toString();

    // Show subtle loading state.
    grid.style.opacity = '0.5';

    fetch(url, { headers: { 'X-Requested-With': 'XMLHttpRequest' } })
```

(phần `.then(...)` giữ nguyên)

- Fallback `.catch`: thay `form.submit();` bằng redirect giữ đủ q+page:

```js
        // Fallback: full navigation with q+page intact (form.submit() would drop page).
        window.location.href = url;
```

Cập nhật comment đầu file: nói GET + X-Requested-With thay vì POST.
